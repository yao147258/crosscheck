# crosscheck

面向**已启动的可信测试项目**的本地 Chromium 浏览器 / HTTP / 可选 PostgreSQL AI 验收工具，执行前须完成所需的配置与人工确认。AI 可自动操作页面、采集脱敏证据，再由执行器与独立 reviewer 双判；FAIL 是疑似 bug，待人工复核。浏览器无网络隔离，不适用于不可信页面或生产环境。

## 安装

```bash
npm i -g crosscheck
# 需要浏览器操作或真实浏览器测试时安装 Chromium；HTTP-only 不启动它
crosscheck --help
```

## 用法

无参数运行 `crosscheck` 在 stdin、stdout 均为 TTY 时进入交互会话。使用 `/init`、`/profile`、`/reqs`、`/plan`、`/review`、`/run`、`/report`、`/impact`、`/status`、`/usage`、`/help`、`/clear` 和 `/exit`；参数与独立命令相同，含空格的路径使用引号，例如 `/review --project "my project"`。`/review` 默认审核启动项目，显式 `--project` 可以覆盖；审核每次重新读取所选项目的确认记录，`q` 或顶层 `Esc` 返回聊天。命令失败显示退出码但不退出会话；Ctrl+C 取消当前操作并等待清理，空闲时使用 `/exit`。

`/status [--project <目录>]` 只读展示推断的项目阶段、待审核数量和最新测试运行；运行缺失、未完成或损坏时明确提示。结果待裁决数量仅针对最新运行，阶段为推断而非完成保证。

每次启动默认新建会话。`/sessions` 列出启动项目的历史；`/resume` 不带参数只列候选并显示用法，`/resume <UUID>` 恢复指定会话的界面历史、有效聊天上下文和用量 ID。不调用模型，不重放历史命令或审核，不自动恢复中断的测试，且不改变 `run --resume`。`/clear` 清空界面和模型上下文，生成新 ID，但保留旧历史和用量；`/exit` 等待写入收尾。

历史位于 `~/.crosscheck/projects/<规范项目路径的 SHA-256>/sessions/<UUID>/`，与用量账本共用项目键。保存聊天、命令、最终输出和状态，不逐条保存实时进度；恢复界面的最终输出按 UTF-8 限制在 64 KiB 并标记截断，成功聊天的完整规范化回复则另存为模型历史。失败聊天和命令不进入模型上下文，模型只使用最近 20 条有效历史消息。未完成操作会标记且不会重放；请勿在多个终端同时操作同一个会话。版本冲突会报错而不覆盖，但已执行的操作仍可能无法归档。损坏会话显示诊断，有可读前缀时可只读恢复。暂存文件只提示，不视为已提交记录。存储要求文件系统支持同目录硬链接。硬链接前会同步记录文件；支持目录同步时还会同步首次追加的父目录和提交后的会话目录。Windows 上 Node 不支持目录同步；在 Windows 或其他不支持目录同步的文件系统上，不保证断电后的目录项持久性。若祖先目录可以穿越但无权同步，仍允许写入并在提交后提示目录项持久性风险。提交后的目录同步错误也会提示风险并保留已提交修订，不要求重试。

`/usage` 查看启动项目的累计模型用量，`/usage --session` 查看当前会话，`/usage --session <UUID>` 查看同项目指定会话的用量。一次性命令只计项目累计；跨项目命令的用量只计入目标项目，但命令及归档输出仍保存在启动项目的当前会话中。`init` 中的笔记请求归入 `init`、画像请求归入 `profile`，共用一次用量收尾，每次实际请求只记一条。此前仅记入账本、未存对话的会话仍可凭已知 ID 查用量，但不能恢复对话。

账本位于 `~/.crosscheck/projects/<规范项目路径的 SHA-256>/usage/`。以 `realpath` 返回的实际路径为准，解析到同一路径的符号链接共用账本；Windows 不强制转小写，不同实际路径仍分开。路径不可解析时不写并告警。哈希不是加密；不保存提示词、对话、工具输出或密钥，但模型名等元数据可能敏感。POSIX 新建账本目录和文件分别使用 `0700` 和 `0600`，在 Windows 上不等价于 ACL，请自行限制用户目录 ACL。

内置 OpenAI 和 Anthropic 进入模型 fetch 才入账，注入模型以 `doGenerate` 为边界。缺失回执或价格会计入未知调用；内置 OpenAI 缺少原始 `cached_tokens` 时，缓存读和费用未知，显式零有效。已知费用是估算，不是服务商账单。启用前的历史不回填，现有运行审计与账本独立。事件先在内存暂存，待使用共享预算的业务收尾后写入。查询会提示损坏或未完整写入的文件；异常退出或写入失败若未留下可检测痕迹，后续查询可能无法发现漏记。

普通文本通过会话启动项目配置的 `planner` 模型回答，只提供当前磁盘上的待审核数量和运行次数摘要及有限聊天历史，不需要确认人，也不提供工具或人工确认权限。模型配置和摘要错误会显示在会话中；写盘前尽力脱敏（包括可读取的配置密钥）；聊天发送和恢复使用相同的规范化文本，可能改变原文含义；待发送历史若命中当前配置密钥，会报错并跳过模型调用，不改写历史，可用 `/clear` 开始新会话。命令仍按原参数运行。脱敏不能识别所有秘密，路径哈希不是加密。会话目录和记录文件在 POSIX 下分别使用 `0700` 和 `0600`，Windows 下请自行限制用户目录的 ACL。内置模型的聊天请求默认尝试写入独立的 `~/.crosscheck/chat-requests.jsonl`；请求体可能包含聊天历史和其他敏感内容。恢复或清空不会关闭或删除此日志。带参数运行时仍使用独立 CLI，各命令的退出码见相应说明。

推荐流程：`init → reqs → review clauses → plan → review cases → run`。`init` 在同一命令中生成笔记与画像、自动确认部分内容，并交接剩余画像的人工审核。

| 命令 | 用途 |
|---|---|
| `init [--refresh] [--openapi <文件>]...` | 缺少配置时先写入默认 `.crosscheck/config.yaml`；扫描并生成 `.crosscheck/notes.md`，以 `auto` 自动确认；生成缺少有效确认的画像，按来源核验结果自动确认部分画像，交接其余待确认画像 |
| `profile [--openapi <文件>]...` | 单独生成画像草稿，要求笔记已确认；不自动确认。`init` 已包含画像生成，两条命令均可重复传入 `--openapi` |
| `reqs --module <id>` | 优先从配置的 `requirementsDocs`（支持目录）提取带来源的条款草稿；仅配置为空时才使用已确认笔记的“需求文档”小节 |
| `review [notes\|profile\|clauses\|cases\|results]` | 交互审核笔记、画像、条款、用例与运行结果 |
| `plan --module <id>` | 画像全部确认、条款确认后，生成用例草稿 |
| `impact [--since <commit>] [--json]` | 只读比较 Git 基线与当前磁盘，解释需求、笔记到画像与用例的级联影响 |
| `run` / `report <runId>` | 执行已确认用例 / 从历史快照离线重建报告 |

`init` 默认跳过已确认笔记；`--refresh` 将旧笔记作为上下文，重新生成并自动确认，人工补充不保证保留。未确认或编辑后失效的笔记直接重跑 `init` 会被覆盖；要保留编辑结果，可先用 `review notes` 人工确认。`init` 和 `profile` 均保留有效已确认画像，`init --refresh` 不覆盖它们。不带 `--refresh` 重跑 `init` 时，若笔记及七份画像均已有有效确认，则无需模型配置，也不会调用模型，但仍执行最终交叉校验。文件与确认记录的复查不提供跨进程原子事务。

`init` 逐条核验未确认的 `api-catalog`、`pages`。至少有一条通过且没有来源读取故障时，才剔除未通过项并整份自动确认；没有通过项（包括原本为空）、来源读取故障，或画像引用了未被扫描登记的显式 `--openapi` 文件时，保留该画像原稿，交给人工审核。核验只证明指定行与摘录匹配，不证明画像语义正确。笔记自动确认不保证有人审阅；笔记只影响画像生成和需求文档范围，不直接决定测什么。

`environments`、`auth`、`data-model`、`fixtures`、`guardrails` 始终由人确认。stdin、stdout 均为 TTY 时，`init` 直接打开仅列待确认画像的审核界面；非 TTY 打印待确认清单并退出 2，可改在交互终端运行 `review profile`。独立 `init` 正常退出审核时若仍有待确认画像，遵循 `review` 的原退出约定（`q` 或顶层 `Esc` 返回 0，`Ctrl+C` 返回 2）；若无需人审或人审正常结束后七画像均已确认，则重新校验笔记确认、七画像格式和交叉引用，并复查画像确认；复查发现笔记缺失、不是有效 UTF-8、笔记或画像未确认或确认失效，或发现必需画像缺失、画像结构或交叉引用不合法时，退出 2。YAML 解析异常等未归入这些检查的错误可能按宿主错误退出 3。`/init` 将审核交接给当前会话，退出审核返回聊天。两种入口的筛选审核界面若提示交叉校验未通过，可按 `f` 打开完整画像审核，编辑并重新确认包括原先隐藏的 `auto` 画像在内的相关文件。

`review profile` 和 `/status` 显示有效已确认画像的确认人。`auto` 是自动确认保留身份，不能用于新的交互式人工确认；历史同名记录不迁移，无法与自动确认区分。`plan` 要求七画像与相关条款已确认；`run` 仍要求用例已确认及凭证、网络授权等门禁。

扫描是预算内的最佳努力，不保证覆盖整个项目；忽略规则、数量和大小等限制可能导致遗漏。项目扫描仅处理根目录 `.gitignore` 的有限子集，不保证支持子目录规则、`**` 或取反语义；按有限名称及扩展名规则忽略常见凭证文件，`.env.example` 是例外，无法识别非标准凭证文件，因此可能扫描本应忽略的非标准秘密。脱敏不能保证识别所有秘密；文件名、摘录和笔记等内容可能发送给配置的模型服务，运行前请检查内容与授权，分享生成物前人工检查。

### 需求文档范围

项目配置的 `requirementsDocs` 非空时优先；仅为空时 `reqs` 才读取已确认笔记的“需求文档”小节。显式配置和人工确认笔记沿用原有路径安全规则。回退到 `auto` 确认的笔记时，`reqs` 要求 `.crosscheck/notes-discovery.json` 中生成时由宿主写入的记录与笔记匹配，并重新扫描、展开目录，对照原登记校验候选路径集合。目录增删导致集合变化、存在未登记文档、扫描或目录展开不完整、文档不可读时，`reqs` 退出 2，不把需求正文交给提取模型。

旧版自动确认笔记缺少登记时，普通重跑 `init` 不会补齐；可用 `init --refresh` 重新生成，或审阅后用 `review notes` 人工确认，也可在项目配置显式填写 `requirementsDocs`。`impact` 仍只读分析，不要求笔记已确认，也不使用这份宿主登记。

### 变更影响分析

```bash
crosscheck impact --project "my project"
crosscheck impact --since HEAD~1 --project "my project"
crosscheck impact --since <commit> --json --project "my project"
```

默认比较 `HEAD` 与当前磁盘（不是单独的暂存区）。被测项目需将相关需求文档、项目配置、笔记、画像、条款和用例纳入 Git；先检查敏感内容，不要加入凭证、全局密钥或运行证据。历史缺失、解析失败或引用缺失会报告不完整，不会冒充“无影响”。

命令不需要模型密钥、不调用模型、不写文件，也不改变确认状态。为避免 Git 惰性获取导致联网或写入，首版拒绝 partial/promisor 仓库及使用 alternates 共享对象库的仓库，请使用完整且独立的仓库。分析与报告达到资源上限时会报告不完整。报告区分实际变更、显式依赖影响、可能影响和分析缺口；自然语言步骤的依赖没有完整记录，可能影响范围会保守扩大。确定依赖不等于确定失败，未发现关联不保证无影响；首版不自动重新生成或使下游失效。`0` 表示分析完整（即使有影响），`2` 表示无效基线/输入不完整/中断，`3` 表示宿主故障。
