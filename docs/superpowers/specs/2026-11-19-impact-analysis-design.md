# 变更影响分析设计说明

- 日期：2026-11-19
- 状态：已确认
- 基础：项目笔记初始化与画像命令拆分（main e51d773）

## 目标与非目标

新增只读 `crosscheck impact`，评估需求、笔记及下游产物变化的级联影响，帮助人工缩小复核范围。首版使用 Git 提交作基线；不调用模型、不建立独立快照、不修改产物或确认记录、不自动重新生成，不改变现有审核或执行门禁。

## 命令

```text
crosscheck impact [--since <commit>] [--json] [--project <目录>]
/impact [--since <commit>] [--json] [--project <目录>]
```

默认基线 HEAD。比较指定提交与当前磁盘最终内容，包含相关新增文件，不分别分析暂存区。报告包含解析后的基线提交 ID。无效基线不回退为空基线或暂存区。

## 分析范围

读取两个版本的项目配置、requirementsDocs 并集中的需求文档、notes.md、七画像、requirements/*.yaml 和 cases/*.yaml。不扫描整个项目源码，也不加载模型配置、运行记录或 approvals。被测项目需要将相关输入和产物纳入 Git，缺失历史会明确报告不完整。

对象键顺序和 YAML 排版不构成实体变化；条款/用例以 ID 为身份，画像按命名条目拆分；数据库连接使用保留身份 `$connection`，避免与合法的具名查询 `connection` 冲突。改名视为删除和新增，不猜测语义对应。自然语言文本仅判断内容变化，不声称理解语义；CRLF 与 LF 统一。用例 covers/fixtures 按集合比较，其他数组保留顺序。

## 依赖与解释

- 需求文档→source.file 引用的条款：可能影响，再经 covers 传播到用例。
- 条款→covers 用例、角色/夹具→显式使用的用例：确定的依赖关系，不等于保证行为会失败。
- 画像内 environment、actor、reset、HTTP operation、SQL query 等引用：按实际 schema 建边；只读查询连接不等同于 SQL fixture 的准备连接。
- 笔记→画像及下游用例：缺少段落级来源映射，保守报告可能影响。
- 没有结构化 API/page/query 引用的自然语言步骤：不得凭名称未出现判定无关，保守列为可能影响。
- guardrails、默认环境等全局执行条件变化需提示用例复核；预算变化不是业务预期变化。

新旧图独立构建和遍历，合并结果但不跨版本拼接路径。图中允许循环，访问去重并保留稳定最短原因链。新增/恢复 active 的条款及用例移除造成的覆盖缺口需要明确提示。

## 输出与完整性

文本及版本化 JSON 使用相同数据，分为实际变更、显式依赖影响、可能影响、分析缺口。每个影响给出根因和依赖链。未发现关联不表示保证不受影响。

缺文件、坏 YAML、非法引用、重复 ID、超限和缺失基线分别表示，不将解析失败视为空集合制造删除。不完整数据仍尽可能分析其他有效输入。已知自然语言精度限制属于报告限制，而不是所有分析都失败的原因。

退出码：0 为范围内分析完整（即使存在影响），2 为无效基线或输入不完整/取消，3 为真实宿主故障。命令进入后的 JSON 预期失败同样输出结构化报告。

## 安全与资源边界

Git 仅通过无 shell 的参数数组执行固定只读命令，先解析 commit ID，再按树和 blob 对象读取；不 checkout、不执行 diff 驱动、过滤器、hooks 或发现的命令。支持 worktree 和仓库内子项目。为避免旧版 Git 静默忽略禁用惰性获取的设置，首版在对象解析前保守拒绝 partial/promisor 仓库及使用 alternates 共享对象库的仓库；用户需使用完整且独立的仓库。

当前文件和基线文件均拒绝逃逸、链接和凭证路径；严格 UTF-8。单文件最多 1 MiB、需求文档每侧合计最多 2 MiB、每侧总读取最多 16 MiB、新旧两侧相关文件候选并集最多 2000 个；进程有超时和输出上限。预算耗尽明确不完整，不能静默截断。分析和报告还限制节点数、工作量、变更数、原因链数量及输出大小；CLI 投影超限同样返回不完整和退出码 2。

输出只允许受控路径、标识、字段位置和原因，不输出正文、配置值、SQL、命令或原始异常。文本转义控制字符。读取期间检测到变化报告不完整，不承诺跨文件原子快照。全程不写缓存、锁或审核记录。

## 验证

纯逻辑测试覆盖条目差异、跨模块依赖、旧引用删除、环、多根因、新旧图隔离、保守影响和覆盖缺口。真实临时 Git 仓库测试覆盖历史提交、磁盘/暂存差异、子目录、Unicode 路径、缺失历史、非法文件、链接及限额。CLI 验证退出码、JSON、/impact 和只读保证，最终运行全量测试、类型检查、构建与独立审查。
