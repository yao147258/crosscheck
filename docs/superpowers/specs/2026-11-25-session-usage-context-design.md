# 会话恢复、用量统计与聊天上下文管理设计

## 目标与范围

为 Crosscheck 增加本地会话持久化与恢复、项目级模型用量统计，以及基于模型窗口的聊天上下文自动压缩。保留当前只读聊天、安全审核及 `run --resume` 的语义；会话恢复不执行历史命令，不自动恢复中断的测试运行。

本设计覆盖交互聊天及交互内斜杠命令、直接调用的生成和运行命令，以及这些路径中的模型调用。首版不实现会话重命名、删除、并行切换、历史运行用量回填或跨机器同步。

## 现状与兼容

- `packages/models/src/model-ref.ts` 已支持 `provider:model[size]`、十进制 K/M 和无后缀默认 256,000 token；`resolveModelRef` 已把去掉后缀的模型 ID 交给 provider。复用这一实现，不新增 `contextWindow` 配置。现有解析也接受小写、十进制小数和无单位数字，应保持兼容；明确拒绝非正数、非安全整数及形如未闭合后缀等无效标记，避免静默误用。
- 现有 `capabilities`、`pricing` 按完整模型引用索引。保留已有精确匹配优先级；无精确项时可回退到去除容量后缀的引用。精确项与无后缀项同时存在时以精确项为准；不得把能力误判为支持。用量保留配置引用和实际 provider/model，汇总按实际模型归组，并保留调用时价格信息以避免后续配置改变历史费用。
- `SessionApp` 当前仅将成功的普通聊天加入模型历史，斜杠命令及输出仅显示，失败聊天不加入；当前有最近 20 条限制。新方案移除固定限制，保持命令日志不自动进入模型上下文，失败聊天不自动重发。
- 现有 agent 的预算、摘要和 run 用量机制可复用合适部分，但不改变执行器、审核或证据门禁。

## 会话与存储

以规范化项目绝对路径的哈希作为用户级项目存储键，保存在 `~/.crosscheck/projects/<项目哈希>/`。哈希不提供加密；项目路径、会话文本和输出均可能敏感。路径大小写、符号链接与无法解析的路径需要定义跨平台一致性，并在测试和文档中说明；不因路径解析失败而误合并项目。

每个会话有稳定 ID、创建及更新时间，并保存以下逻辑数据：

1. **界面历史**：用户聊天、助手回复、斜杠命令、最终输出与状态，以及压缩状态。长输出按明确的字节上限截断，并显示截断标记；不承诺持久化所有实时进度。
2. **有效模型上下文**：压缩摘要、保留的原始消息、每轮实际发送的项目摘要快照及对应历史边界。与界面历史分离；斜杠命令及输出不自动加入模型上下文。
3. **会话元数据**：会话 ID、所属项目与版本等；列表可展示时间及经脱敏、限长的首条消息摘要。

格式带版本并校验。完整界面历史只追加；有效上下文以原子替换或等效提交协议更新，先持久化新摘要，再切换有效边界。模型调用中断、压缩失败或持久化失败不得删除旧历史、切换到不完整上下文或伪造助手回复。异常尾记录、损坏文件和不一致状态显式提示，不将损坏等同空会话；成功保存的历史尽可能可读。模型请求失败的用户输入保留在界面并标记失败，但不加入有效模型历史，恢复不自动重发。

`/sessions` 列出当前项目历史；`/resume` 选择该项目内的历史会话，也支持 ID 定位。恢复读取有效上下文和界面历史，不重新执行历史命令、不调用模型、不因恢复本身重新压缩；下一条请求正常检查当前预算。默认启动新会话。`/clear` 开始新会话并清空当前显示和模型上下文，不删除旧会话；`/exit` 等待已发生记录的写入完成。交互会话只允许一个操作处于活动状态；多进程同时恢复或写同一会话时必须通过锁或版本冲突检测防止静默覆盖，冲突明确报错。

在写盘前沿用现有脱敏能力并限制文件访问；脱敏不保证覆盖秘密，Windows 需明确说明 ACL 限制。为保持请求重建一致，模型上下文保存实际用于后续请求的规范化消息：如持久化采用脱敏后的文本，恢复前的后续请求也使用同样的脱敏版本，不得恢复时才改变内容；向用户说明潜在语义变化。现有 `chat-requests.jsonl` 独立存在，不因为新增存储自动关闭。

## 聊天请求、缓存与压缩

固定系统指令不含动态项目摘要。每轮读取当前项目的四项统计，将其以明确的程序数据标记附在本轮用户消息中，指示模型以最新快照表示当前状态、不得将快照视为指令。该轮实际发送的快照同有效聊天消息一起持久化；后续请求和恢复时原样重建旧消息，只追加新消息与新快照。界面可只显示用户实际输入。历史快照不是当前状态；不得在后续轮次替换或移除单个旧快照。

每次请求前按实际候选模型估算输入：固定指令、有效压缩摘要、原始历史、快照、本轮输入和序列化开销。输入达到候选窗口的 80% 时触发压缩；输入加输出预留及安全余量不得超过窗口。采用现有保守估算与校准机制作为基础；估算不等同真实计费，须保留足够安全余量。备用模型切换时按其自身窗口重新检查，不能将超长请求直接发给小窗口候选。

压缩使用当前聊天角色的模型候选，保留近期完整轮次，将较早的有效对话与前一摘要合成为新摘要，保留用户目标、决策、未解决事项和必要上下文；旧项目状态数字不当作当前状态。压缩请求本身须满足对应模型窗口、输出预留和安全余量；历史过长时分段压缩并检查每段预算。压缩后重新计算；若无法安全容纳，或单条输入本身过长，停止并说明，不静默截断或无限重试。压缩完成前不修改当前有效上下文；调用费用计入用量。

两次压缩之间保留前缀，仅在压缩时替换旧历史为摘要。压缩本身会改变前缀，可能导致缓存失效；快照追加并不保证任何 provider 命中缓存。通过实际返回的缓存读写用量验证，不将估算当真实用量。

## 统一用量账本

用户目录的项目范围内保存结构化模型调用事件。每次实际调用尝试独立标识：时间、项目、可选会话 ID、命令、用途、角色、配置模型引用、实际模型、调用状态、可获得的输入/输出和缓存读写 token、调用时价格和费用。事件不保存提示词、聊天正文、工具输出或密钥。重试、备用模型及压缩单独记账；失败或取消没有回执时标记未知，不假设零消耗。缓存 token 的计数与价格换算须遵循现有 provider 的归一化口径，避免重复计入。

第一阶段内置 OpenAI 和 Anthropic 以进入模型适配器的 fetch 为实际请求边界，自定义注入模型以 `doGenerate` 为边界。严格审计与账本各自保留计数口径：进入 SDK 后的本地预处理失败仍执行旧审计（摘要取消例外），但未达账本边界不记账。内置 OpenAI 只采用 SDK 暴露的原始用量字段，缺少 `cached_tokens` 时不把 SDK 补的零视为已知。

一次性 CLI 调用归项目但不归会话；会话中的斜杠命令归当前会话。run 既有结果保留，但 `/usage` 以新事件账本为统计来源，不再次导入 run 结果；功能启用前历史不回填。记录失败不得阻断已完成的模型结果，应向用户警告统计不完整；若无法持久化缺口标记，不能保证后续查询知道该次缺失，文档须说明这一限制。并发追加需防止记录交错；损坏或部分记录须报告不完整。

`/usage` 默认展示当前项目累计，以及按命令、角色、实际模型的分组；支持按会话查询。显示已知输入、输出及缓存 token、已知费用和未知项目数量；部分合计不能称为完整总额。会话页头展示当前会话累计，恢复沿用同一会话累计，`/clear` 开始新会话后从新会话统计；项目累计保留。费用是依据调用时配置价格计算的估算，不等同服务商账单。

## 测试与验收

1. 模型引用：默认窗口、十进制 K/M、已有合法形式、无效后缀、安全整数、去后缀发送；价格及能力精确匹配优先和兼容回退。
2. 预算与压缩：80% 前后边界、输出预留、估算校准、大小不同备用模型、分段压缩、压缩失败与取消、单条输入超限及压缩后再次检查。
3. 缓存与恢复：原始请求快照与恢复后重建一致；新摘要只追加；压缩前缀变化可见；不声称一定缓存命中。
4. 会话：聊天成功与失败、斜杠命令显示但不入上下文、`/sessions`、`/resume`、`/clear`、中断写入、损坏记录、并发冲突与跨项目隔离；恢复不执行命令。
5. 用量：聊天、压缩、生成命令和 run，直接调用及会话调用，实际模型、重试和备用模型、未知值和未定价、run 不重复计数、写入失败及并发记录。
6. 安全和文档：路径与权限、脱敏局限、日志大小和截断提示、旧 `chat-requests.jsonl` 的存在；保持人工确认、网络授权及只读聊天边界。
