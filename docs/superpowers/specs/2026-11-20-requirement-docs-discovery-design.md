# 需求文档目录支持与笔记驱动的需求文档发现

日期：2026-11-20
状态：设计已口头确认，待书面评审

## 背景与目标

现状：

- `requirementsDocs` 只能在项目 `.crosscheck/config.yaml` 中逐个写文件路径，默认为空数组。
- `reqs` 在其为空时直接退出 2；`impact` 也只读 config 里的该字段。
- `notes.md` 是模型生成的自由 Markdown，程序不解析其内容。

目标：

1. `requirementsDocs` 支持目录，递归展开其中的 `.md` 文件。
2. `init` 在笔记中给出疑似需求文档清单（只写草稿），由人在 `review notes` 中审核确认；`reqs`、`impact` 读取已确认笔记里的清单。发现与落盘分离，不由程序改写 `config.yaml`。

非目标：

- 不支持 glob（如 `docs/**/*.md`）。
- 不支持 `.md` 以外的文件类型（Word、PDF、txt 等）。
- 不自动合并 `reqs` 到 `init`：`reqs` 仍按模块单独执行。
- 不改变 `NotesTextSchema`，旧笔记保持合法。

## 设计

### 1. 目录展开函数（discovery 包，新文件）

`expandRequirementDocs(projectRoot, entries, signal)`，返回排序后的项目相对文件路径数组。

规则：

| 项 | 规则 |
|---|---|
| 目录写法 | 以 `/` 结尾（`docs/prd/`）；其余条目按文件处理 |
| 递归 | 递归展开，最大深度 8 |
| 文件类型 | 仅 `.md`，扩展名不区分大小写；其他文件忽略且不报错 |
| 文件数上限 | 100，超限报错，不静默截断 |
| 符号链接 | 目录与文件均跳过，并输出诊断 |
| 凭证、不安全路径 | 递归中静默跳过（沿用 `isSafeProjectPath`/`isCredential`）；显式写出的文件路径仍报错 |
| 忽略目录 | `node_modules`、`.git`、`.crosscheck` |
| 规范化 | 路径统一为 `/`，去重（含目录包含关系），字典序排序 |
| 空结果 | 目录不存在或展开后无 `.md`，报错 |

复用 `createProjectReader().list`，路径安全检查只保留一份。读取后总大小 2 MiB 的限制保留在 `readRequirementDocuments`。

### 2. 笔记中的需求文档小节

- 约定 `## 需求文档` 小节，每行形如 `` - `路径` 说明文字 ``，路径位于反引号内，其后说明文字被程序忽略。
- 解析函数 `parseNotesRequirementDocs(text): string[]`（core 包）。无该小节返回空数组。模型未发现时写"未发现"，解析结果同样为空。
- 小节是笔记正文的一部分，确认与哈希机制不变。

### 3. 命令行为

**init**：修改 `NOTES_SYSTEM` 提示词，要求生成该小节，优先给目录并附依据。`--refresh` 时旧笔记原样传给模型，保留人工补充。

**reqs**：取清单优先级：

1. `config.yaml` 的 `requirementsDocs` 非空时使用它。
2. 否则使用已确认笔记的小节；此时笔记未确认则报错并提示先运行 `review notes`。
3. 两处都为空时提示：在 config 登记，或在笔记的“需求文档”小节登记并确认。

清单经展开函数得到文件列表后进入原有读取与提取流程。

**review notes**：无需修改。

### 4. impact

- 基线与当前两侧各自按同样优先级取清单（config 非空用 config，否则用该侧 notes 小节）。
- 当前侧从磁盘展开；基线侧从 Git 对象（`git.entries`）按路径前缀展开，不依赖磁盘。
- `core/impact/dependencies.ts` 的来源范围集合改为“所有需求文档节点的文件”，不再使用 config 字符串。
- 条款来源始终记录展开后的具体文件路径，不记目录。
- impact 读取笔记小节时不检查确认状态（只读分析，基线侧也无法可靠判断确认状态）。

## 错误处理

- 展开超限、目录为空或不存在、路径不安全：明确报错，退出码沿用 `reqs` 现有约定（2）。
- `impact`：基线侧展开失败或超限时输出“分析不完整”诊断，退出码 2。
- 取消信号在展开、读取各阶段检查。

## 测试

- 展开函数：多层嵌套、非 `.md` 忽略、符号链接、凭证文件、文件数超限、空目录、重复与包含关系、反斜杠写法、排序稳定。
- 解析函数：无小节、“未发现”、格式异常行、带说明文字的行。
- reqs：config 优先、笔记未确认被拒、两处为空、目录清单端到端。
- impact：目录内新增与删除 `.md` 被识别；基线侧从 Git 展开；来源范围按展开后文件匹配。
- init：用脚本模型验证提示词输出结构，不验证真实模型质量。
